# Day 11 – Apache Tomcat Commands

This file contains the important commands used during **Day 11 – Apache Tomcat Web Application Deployment**.

The commands are organized in the same order in which they are useful during the implementation, verification, and troubleshooting process.

---

# 1. Connect to App Server 2

```bash
ssh <app-server-user>@stapp02
```

### Purpose

Connects to **App Server 2** (`stapp02`) from the Jump Host.

---

# 2. Verify the Hostname

```bash
hostname
```

### Purpose

Confirms that you are working on the correct server.

Expected:

```text
stapp02
```

---

# 3. Verify Java

```bash
java -version
```

### Purpose

Tomcat is a Java-based application server, so Java must be available before Tomcat can run.

This command displays the installed Java runtime version.

---

# 4. Install Apache Tomcat

```bash
sudo dnf install tomcat -y
```

### Purpose

Installs the Apache Tomcat package using the DNF package manager.

### Breakdown

```text
sudo
```

Runs the command with administrative privileges.

```text
dnf
```

Red Hat-family package manager.

```text
install
```

Tells DNF to install a package.

```text
tomcat
```

The Apache Tomcat package.

```text
-y
```

Automatically answers yes to the package installation prompt.

---

# 5. Verify the Tomcat Package

```bash

```

### Purpose

Checks whether Tomcat packages are installed.

### Breakdown

```text
rpm -qa
```

Lists all installed RPM packages.

```text
|
```

Pipes the output of the first command into the next command.

```text

```

Filters the output and displays only entries containing `tomcat`.

# 6. Open Tomcat Configuration

```bash
sudo vi /etc/tomcat/server.xml
```

### Purpose

Opens Tomcat's main configuration file.

The file contains important settings such as:

- HTTP Connector
- Shutdown port
- HTTPS Connector
- Host configuration
- Server configuration

---

# 7. Verify the Required HTTP Port

```bash
sudo grep -n '6400' /etc/tomcat/server.xml
```

### Purpose

Checks whether port `6400` is present in the Tomcat configuration.

### Breakdown

```text
grep
```

Searches text inside a file.

```text
-n
```

Displays the line number along with the matching line.

```text
'6400'
```

The exact text being searched for.

```text
/etc/tomcat/server.xml
```

Tomcat's main configuration file.

---

# 8. Configure the HTTP Connector

The HTTP Connector should use the required port:

```xml
<Connector port="6400" protocol="HTTP/1.1"
           connectionTimeout="20000"
           redirectPort="8443" />
```

### Purpose

Configures Tomcat to accept HTTP requests on TCP port `6400`.

The important part is:

```text
port="6400"
```

The HTTP port must remain `6400` because it is explicitly required by the challenge.

---

# 9. Copy the WAR Application

If the provided WAR file is located in `/tmp/ROOT.war`:

```bash
sudo cp /tmp/ROOT.war /var/lib/tomcat/webapps/
```

### Purpose

Copies the Java web application archive into Tomcat's web application directory.

Tomcat automatically detects and deploys WAR files placed inside:

```text
/var/lib/tomcat/webapps/
```

---

# 10. Verify the WAR File

```bash
ls -lh /var/lib/tomcat/webapps/
```

### Purpose

Lists the files in Tomcat's web application directory.

The expected application archive is:

```text
ROOT.war
```

---

# 11. Why `ROOT.war` Is Used

No command is required specifically for this concept, but the important deployment path is:

```text
/var/lib/tomcat/webapps/ROOT.war
```

Because the WAR file is named:

```text
ROOT.war
```

Tomcat deploys it as the root application.

Therefore:

```text
ROOT.war
      ↓
/
      ↓
http://stapp02:6400
```

Instead of:

```text
http://stapp02:6400/ROOT
```

# 17. Search for the HTTP Port in the Logs

```bash
sudo journalctl -u tomcat --no-pager | grep 6400
```

### Purpose

Checks the Tomcat logs for references to port `6400`.

A useful log entry is:

```text
Initializing ProtocolHandler ["http-nio-6400"]
```

This confirms that Tomcat initialized the HTTP Connector on port `6400`.

---

### Breakdown

```text
-n
```


```text
-p
```

```text

```

Pipes the result into `grep`.


Filters the output for port `6400`.

# 23. Check the Tomcat Configuration File


This is useful when troubleshooting HTTP or HTTPS ports.

---

# 24. Check the Shutdown Port Configuration

```bash
sudo grep -n '<Server' /etc/tomcat/server.xml
```

### Purpose

Displays the Tomcat `<Server>` configuration line.

The `<Server>` element can contain the Tomcat shutdown port.

Conceptually:

```xml
<Server port="SHUTDOWN_PORT" shutdown="SHUTDOWN">
```

The important rule is that the shutdown port must not conflict with the HTTP Connector port.

For this challenge:

```text
HTTP Port       → 6400
Shutdown Port   → Separate unused port
```

---

# 25. Understanding the Port Conflict

The error encountered during the task was:

```text
java.net.BindException: Address already in use
```

Tomcat also reported:

```text
Failed to create server shutdown socket
```

This indicated that Tomcat's shutdown socket was attempting to bind to a port that was already occupied.

The HTTP Connector had already successfully initialized on:

```text
6400
```

Therefore, the HTTP port was not the problem.

The correct solution was to keep:

```text
HTTP Connector → 6400
```

and configure the shutdown socket to use a separate available port.

# 26. Important Troubleshooting Sequence

When Tomcat failed:

```bash
sudo systemctl status tomcat
```

Then inspect the logs:

```bash
sudo journalctl -u tomcat -n 50 --no-pager
```

Look for port-related errors:

```bash
sudo journalctl -u tomcat --no-pager | grep -E 'BindException|Address already in use|shutdown socket'
```

Then inspect the configured HTTP port:

```bash
sudo grep -n '6400' /etc/tomcat/server.xml
```

Check whether the HTTP port is listening:

```bash
sudo ss -lntp | grep 6400
```

After correcting the shutdown-port conflict:

```bash
sudo systemctl restart tomcat
```

Verify:

```bash
sudo systemctl status tomcat
```

Finally test:

```bash
curl http://stapp02:6400
```
