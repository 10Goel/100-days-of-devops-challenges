## About this repository

This repository documents my completion of **KodeKloud's 100 Days of DevOps** hands-on challenge series, completed on **November 5, 2026**. It serves as a practical engineering learning log: configuring systems, deploying applications, automating repetitive operations, troubleshooting failures, and provisioning infrastructure with code.

Each numbered directory corresponds to an individual challenge. Depending on the task, directories contain walkthroughs, commands, notes, configurations, playbooks, or pipeline examples. The goal is to show **what I implemented, how I verified it, and what I learned**, not just a completion badge.

> **Scope:** These are guided practice-lab implementations, not claims of production ownership or a fully deployed enterprise platform. Some lab assets and infrastructure are ephemeral, and exact commands may depend on the KodeKloud environment.

## Engineering lessons reinforced

- **Troubleshoot before guessing:** inspect services, logs, connectivity, build output and live infrastructure state.
- **Automate repetitive work:** use versioned Jenkins pipelines and Ansible playbooks to make execution repeatable.
- **Treat deployments as verifiable operations:** test application behavior and validate actual resource state after changes.
- **Use infrastructure as code:** define cloud infrastructure declaratively, validate plans, and confirm convergence.
- **Apply least privilege:** scope IAM permissions, restrict ingress and avoid publishing keys or credentials.
- **Document what matters:** capture commands, failures, fixes and trade-offs so another engineer can reproduce the reasoning.

## Responsible use and security

These exercises were completed in temporary training environments. **Do not reuse lab credentials, internal hostnames, hard-coded AMIs or permissive security rules in production without review.** Before using any example, verify compatibility and permissions in your own environment.

If you fork or clone this repository, avoid committing `.tfstate` files, private keys, passwords, `.env` files or cloud access tokens. The repository is intended as a learning reference, not a production-ready deployment bundle.
