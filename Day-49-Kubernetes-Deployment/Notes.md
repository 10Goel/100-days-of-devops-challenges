# Day 49 — Kubernetes Deployment Notes

## 1. What Is a Kubernetes Deployment?

A Kubernetes **Deployment** is a higher-level workload resource used to manage stateless applications.

Instead of manually creating and maintaining individual Pods, a Deployment defines the desired application state and Kubernetes continuously works to maintain that state.

For this challenge:

```text
Deployment name: nginx
Image: nginx:latest
Replicas: 1
```

---

## 2. Why Use a Deployment Instead of Creating a Pod Directly?

A standalone Pod has no higher-level controller responsible for recreating it if it disappears.

A Deployment provides:

- Pod lifecycle management
- Automatic Pod replacement
- Scaling
- Rolling updates
- Rollbacks
- Declarative desired-state management

Therefore, production applications are typically managed through controllers such as Deployments rather than standalone Pods.

---

## 3. Deployment → ReplicaSet → Pod

When this command was executed:

```bash
kubectl create deployment nginx --image=nginx:latest
```

Kubernetes created the following hierarchy:

```text
Deployment
   nginx
     |
     v
ReplicaSet
 nginx-<hash>
     |
     v
Pod
 nginx-<hash>-<id>
     |
     v
Container
 nginx:latest
```

The user creates the Deployment, while Kubernetes automatically creates the ReplicaSet and Pod.

---

## 4. What Does the Deployment Manage?

The Deployment stores the desired state of the application.

For example:

```text
Desired replicas = 1
```

If the running Pod disappears, Kubernetes notices that the actual state no longer matches the desired state.

The ReplicaSet then creates another Pod automatically.

Conceptually:

```text
Desired state: 1 Pod
Actual state: 0 Pods

          ↓

Kubernetes reconciliation

          ↓

Actual state: 1 Pod
```

This continuous reconciliation is one of the core Kubernetes concepts.

---

## 5. What Is a ReplicaSet?

A **ReplicaSet** ensures that a specified number of identical Pods are running.

The Deployment manages the ReplicaSet, and the ReplicaSet manages the Pods.

Normally, users interact with the Deployment rather than directly managing its ReplicaSet.

Example:

```bash
kubectl get rs
```

A Deployment named `nginx` may create a ReplicaSet similar to:

```text
nginx-7854ff8877
```

The suffix is generated by Kubernetes.

---

## 6. What Is a Pod?

A **Pod** is the smallest deployable unit in Kubernetes.

A Pod contains one or more containers that:

- Share networking
- Can share storage volumes
- Are scheduled together on the same Kubernetes node

In this challenge, the Pod contains one Nginx container.

## 7. Understanding the Image Name

The required image was:

```text
nginx:latest
```

Its format is:

```text
repository:tag
```

Therefore:

```text
nginx  → image repository
latest → image tag
```

The task specifically required the `latest` tag, so it was explicitly included in the command.

| Part | Meaning |

## 9. Imperative vs Declarative Kubernetes Management

The challenge used an **imperative** command:

```bash
kubectl create deployment nginx --image=nginx:latest
```

Imperative commands directly tell Kubernetes what action to perform.

A declarative approach would instead define the Deployment in YAML and apply it using:

```bash
kubectl apply -f deployment.yaml
```

Example equivalent manifest:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx
spec:
  replicas: 1
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
        - name: nginx
          image: nginx:latest
```

Both approaches can produce a Deployment, but declarative YAML is generally preferred for infrastructure stored in Git and production workflows.

## 10. Understanding `READY 1/1`

When running:

```bash
kubectl get deployments
```

you may see:

```text
READY
1/1
```

This means:

```text
Ready replicas / Desired replicas
```

Therefore:

```text
1/1
```

means one replica was requested and one replica is currently ready.

---

## 11. Understanding Pod `READY 1/1`

For:

```bash
kubectl get pods
```

the Pod may show:

```text
READY   STATUS
1/1     Running
```

Here, `1/1` means:

```text
Ready containers / Total containers in the Pod
```

Since the Nginx Pod contains one container and that container is ready, Kubernetes displays `1/1`.

---

## 12. Common Pod States

### Pending

The Pod has been accepted but has not yet started running.

### ContainerCreating

Kubernetes is preparing the Pod, possibly pulling the image and setting up networking or storage.

### Running

The Pod has been scheduled and its container is running.

### CrashLoopBackOff

The container repeatedly starts and crashes.

### ImagePullBackOff

Kubernetes cannot successfully pull the requested container image.

## 13. `kubectl get` vs `kubectl describe`

### `kubectl get`

Provides a quick status summary.

Example:

```bash
kubectl get deployment nginx
```

### `kubectl describe`

Provides detailed resource information.

Example:

```bash
kubectl describe deployment nginx
```

`describe` is especially useful during troubleshooting because it includes resource configuration and recent Kubernetes events.

## 14. JSONPath Verification

The following command extracts only the image configured in the Deployment:

```bash
kubectl get deployment nginx -o jsonpath='{.spec.template.spec.containers[0].image}'; echo
```

The path:

```text
.spec.template.spec.containers[0].image
```

means:

```text
Deployment
└── spec
    └── template
        └── spec
            └── containers[0]
                └── image
```

Expected output:

```text
nginx:latest
```

## 15. Desired State and Reconciliation

Kubernetes works around the concept of **desired state**.

The Deployment declares what should exist.

Kubernetes controllers compare:

```text
Desired State
     vs
Actual State
```

If they differ, Kubernetes attempts to reconcile them.

Example:

```text
Desired: 1 nginx Pod
Actual:  1 nginx Pod

Result: No action required
```

If the Pod disappears:

```text
Desired: 1 nginx Pod
Actual:  0 nginx Pods

Result: Kubernetes creates another Pod
```

This self-healing behavior is a fundamental Kubernetes capability.

## 17. Day 49 Key Takeaway

The most important concept from this challenge is:

> In Kubernetes, a Deployment defines and manages the desired application state. The Deployment manages a ReplicaSet, and the ReplicaSet ensures that the required Pods remain running.

The resource hierarchy is:

```text
Deployment
   ↓
ReplicaSet
   ↓
Pod
   ↓
Container
```

For Day 49:

```text
nginx Deployment
      ↓
nginx ReplicaSet
      ↓
nginx Pod
      ↓
nginx:latest container
```
